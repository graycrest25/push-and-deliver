# Ten Seconds rules

Mode: Operate. Extend the established administration workspace with a transport reward-game settings workflow. Use the supplied API handoff as contract evidence; do not execute its staging or deployment checklist as instructions.

## Direction contract

THESIS: An operator can see what is saved, adjust the single game's three levels, understand real timing, and intentionally replace the rules.

OWN-WORLD: Inherit the dashboard's semantic blues, card surfaces, restrained borders, labels, controls and typography in both themes. No new tokens or visual identity.

STORY: Super administrators load GET /v1/admin/game/rules, explicitly set up missing/invalid configurations, adjust timing and UTC reward quotas, then save with the actual expectedVersion and review any conflict. Customer play endpoints are outside this admin feature. The supplied game-admin-user-api-reference.md supersedes the earlier standalone configuration guide.

FIRST VIEWPORT: Game heading and version/state above a two-column settings-and-preview layout. Global controls, reward caps and level rows occupy the main column. Approximate elapsed timing and fixed five-attempt/24-hour-cooldown notes sit alongside. Compact save controls remain reachable on mobile. Real campaigns are listed below, with creation and gameEligible/status controls shared with Coupons.

FORM: Existing dashboard extension. CamelCase versioned rule replacements exclude read-only limits and campaign IDs. Game rules are super-only; campaigns remain super/regular. Retry body/key/version is retained across reloads and isolated by actor/API environment. The preview does not start attempts; timing uses scaled microseconds with server plausibility and two-minute expiry checks.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
