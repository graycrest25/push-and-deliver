SCOPE AND LIMITS
- Current local Next.js webapp was checked against the live backend configured in BASE_URL. This is not a deployed-frontend audit.
- All 35 static admin destinations, their tested report/configuration tabs, and 9 discovered detail URLs were visited. Not every database record or every filter/pagination combination was sampled.
- Only read operations and authentication login/logout were exercised. Role changes, settings writes, coupon issuance, support replies/claims, wallet actions, notification sending, job replay, uploads and destructive commands were not executed.
- General notifications, account security and Files were visited, but their mutation-only controls or file lifecycle were not tested. A page without a read failure is not proof that its write endpoints work.
- Detail routes requiring records from failed/empty lists were not tested: user/rider/vendor/merchant profiles, ride/marketplace orders, office/tariff/catalogue details, withdrawal detail and payment receipt detail. No made-up identifiers were used to manufacture 404s.
- Referral detail and merchant transaction/product placeholder routes have no established record-detail behavior; they were not exercised using fabricated IDs.
- Password recovery, Google OAuth provider sign-in and revoked/other-subtype sessions were outside this supplied password-admin audit.
- Expected unauthenticated startup 401s, React development-mode aborted duplicate requests, and corrected audit-script selector errors are excluded from failures.
- Error bodies are the actual JSON returned through the proxy; BASE_URL, passwords, cookies and access/refresh credentials are omitted. Header descriptions reflect server proxy behavior, not browser-visible bearer headers.
- No application implementation changes were made during this audit.
